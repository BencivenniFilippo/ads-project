# Distributed Word Count Service

This repository contains a small distributed-systems lab project that exposes
a word-count service over [RPyC](https://rpyc.readthedocs.io/). The service
counts occurrences of a word in text files and uses Redis to cache repeated
`(file, word)` queries.

The current deployment is intentionally simple:

```text
client ── RPyC/TCP ──> server ── Redis ──> cache
                         │
                         └── Texts/*.txt
```

There is currently one application server and one Redis instance. The project
does **not** contain or start a load balancer, server replicas, or a separate
routing service.

## Requirements

- Docker Engine
- Docker Compose v2 (`docker compose`)

The Docker images use Python 3.9 and install the dependencies listed in
[`requirements.txt`](requirements.txt). A local Python installation is not
needed for the Docker-based workflow.

## Quick start

Build the images and start Redis and the server:

```bash
docker compose build server client
docker compose up -d --wait cache server
```

The Compose network is private and no host ports are published by the current
[`docker-compose.yaml`](docker-compose.yaml). The client must therefore be run
as a Compose service. Redis is available to the server as `cache:6379`, and
the server is available to the client as `server:7777`.

Run one benchmark with the default configuration:

```bash
docker compose run --rm client
```

The client writes logs to standard error and prints one CSV line to standard
output:

```text
rate,duration,avg_ms,p99_ms,max_lag_ms,errors,n_requests
```

Stop and remove the containers with:

```bash
docker compose down
```

## Benchmark client

The client first retrieves the list and contents of the available text files
through RPyC, builds a vocabulary, creates a deterministic workload, and then
sends requests at the configured rate. Each request opens an RPyC connection,
calls `exposed_word_count`, and records the round-trip latency.

The cache workload is selected with `HIT_RATE`:

- `0` (default): every measured `(file, word)` pair is unique.
- `50`: each selected pair is requested twice, producing an approximately
  half-cold, half-repeated workload.
- `100`: one pair is prewarmed and then reused for every measured request.

The supported client variables are:

| Variable | Default | Description |
| --- | --- | --- |
| `RATE` | `50` | Target requests per second |
| `DURATION` | `20` | Benchmark duration in seconds |
| `SEED` | `42` | Random seed used to build the workload |
| `HIT_RATE` | `0` | Cache workload mode: `0`, `50`, or `100` |
| `BENCH_FILES` | `LOTR_1_TheFellowshipOfTheRing.txt,LOTR_3_ReturnOfTheKing.txt,Pulp_Fiction.txt,Forrest_Gump.txt` | Comma-separated text files to use |
| `LOAD_BALANCER_HOST` | `server` in Compose | RPyC server hostname; the variable name is retained for client compatibility |
| `LOAD_BALANCER_PORT` | `7777` | RPyC server port; the variable name is retained for client compatibility |
| `CLIENT_NAME` | `client` | Name included in client log messages |

For example:

```bash
docker compose run --rm \
  -e RATE=100 \
  -e DURATION=10 \
  -e HIT_RATE=50 \
  -e SEED=123 \
  client
```

## Reproducible Phase 2 experiment

[`run_phase2.sh`](run_phase2.sh) runs the single-server experiment for rates
`50 70 90 110 130`, with two repetitions per rate and a ten-second duration.
Before each measured repetition it flushes Redis. It also performs a short
warm-up whose requests are excluded from the measurements.

Run it from the repository root:

```bash
bash run_phase2.sh
```

The script starts only `cache` and `server`, then stores results in a
timestamped directory under `Experiments/phase2_<timestamp>/`:

- `results.csv` — raw measurements for each rate and repetition
- `manifest.txt` — experiment configuration
- `client.log` — client progress, summaries, and errors
- `average_latency.png` — average latency by rate
- `p99_latency.png` — p99 latency by rate
- `error_rate.png` — request error rate by rate

The plots are generated by [`plot_results.py`](plot_results.py) from
`results.csv`; the CSV is the source of truth.

To use a different cache workload:

```bash
HIT_RATE=50 bash run_phase2.sh
```

## RPyC service API

The service implemented in [`server.py`](server.py) listens on port `7777` by
default and exposes:

- `exposed_word_count(file, word)` — returns the case-insensitive number of
  occurrences of `word` in `Texts/<file>`, using Redis when a cached result is
  available.
- `exposed_txt_file_list()` — returns the names of the `.txt` files in
  `Texts/`.
- `exposed_read_file(file)` — returns the complete contents of
  `Texts/<file>`.

The server supports these environment variables:

| Variable | Default | Description |
| --- | --- | --- |
| `RPC_PORT` | `7777` | RPyC listening port |
| `CACHE_HOST` | `cache` | Redis hostname |
| `CACHE_PORT` | `6379` | Redis port |
| `SERVER_NAME` | `server` | Name included in server log messages |

The server logs a cache summary on the first request and every 50 requests.
Its logs can be inspected with:

```bash
docker compose logs --no-color server
```
